## 1. 范围与事实来源

- 目标硬件：FoloToy AI Passport，ESP32-C3、8 MB Flash、无 PSRAM；240 x 320 竖屏，最终画面带 30 px 圆角遮罩；
  UP、DOWN、OK 三个键共用一条 ADC 电阻分压线；ES8311 扬声器编解码器；CW2017 电量计。ESP-IDF 5.5.3，LVGL 9.5.0。
- 范围内：三个阶段、练习组（session）状态机、强制的错题停留、防敷衍突击检查、“太简单”、暂停卡、跨练习组的间隔重复、
  48 条测试词库、离线单词音频（本地私有音频包；从仓库构建的固件没有单词音频）、合成提示音、音量与带视觉替代的静音、空闲变暗与深度睡眠、电量指示、生成的字体子集，以及带经验值的宠物。
- 已取消：通过云服务给发音打分。范围外：一切网络服务（Wi-Fi、BLE、配网、在线 TTS、NTP、OTA、云同步）。
- 已延后：跟读练习、用户词库流水线（只确定了数据契约，见第 13 节）、分音素拼读音频、意思配图、家长菜单、多用户和进度重置界面。
- 事实来源按以下顺序：`main/` 中的头文件（每个头文件记录本模块的契约）、`main/vocab_config.h`（全部可调数值）、
  `main/vocab_strings.h`（全部中文界面字符串）和 `main/vocab_bank.c`（测试词库）。本文只做概括；与代码不一致时以代码为准，并须修正本文。

## 2. 架构

### 2.1 模块图

```text

                    vocab_app_start()、按键；on_key() 只负责入队
vocab_app.c         应用任务：按键队列、引擎、命令执行、NVS 适配、
                    保存闸门、在 bsp_lvgl_lock() 下渲染、深度睡眠流程
  vocab_engine      （纯逻辑）设备与主机模拟共用的唯一入口
    vocab_input     （纯逻辑）原始 BSP 事件 -> 意图，规则 R1-R9
    vocab_idle      （纯逻辑）ACTIVE -> DIM -> OFF -> SLEEP 时间线
    vocab_session   （纯逻辑）HOME -> 卡片 -> SUMMARY、卡片队列、定时器、结果
      vocab_srs         （纯逻辑）结果规则、选词
      vocab_anticheat   （纯逻辑）“认识”连续自评、突击检查目标、回滚

      vocab_stage1/2/3  （纯逻辑）每个模块负责一张卡，经由 vocab_stage.h

      vocab_pet         （纯逻辑）经验、等级、称号、宠物阶段
  vocab_store       （纯逻辑）基于注入的键值接口的持久化策略
    vocab_progress  （纯逻辑）meta 与进度块编解码、CRC、指纹、迁移、NVS 容量
  vocab_audio       （设备）音频任务：vocab_clips（音频包解析）+ vocab_adpcm + vocab_tone
```

### 2.2 纯逻辑核心与设备层

| 层 | 模块 | 规则 |
| --- | --- | --- |
| 纯逻辑核心 | `vocab_engine`、`vocab_session`、`vocab_srs`、`vocab_input`、`vocab_idle`、`vocab_stage1/2/3`、`vocab_lure`、`vocab_anticheat`、`vocab_cloze`、`vocab_pet`、`vocab_progress`、`vocab_store`、`vocab_layout`、`vocab_view`、`vocab_bank`、`vocab_rng`、`vocab_clips`、`vocab_adpcm`、`vocab_tone` | C11，不包含 ESP-IDF 或 LVGL 头文件，不分配堆内存，不读时钟（时间以毫秒为单位作为 `now` 传入）；随机数只来自注入的 PCG32 生成器；阶段模块没有可变的静态状态；在 `-std=c11 -Wall -Wextra -Werror` 下零警告；有主机测试覆盖 |
| 设备层 | `main.c`、`vocab_app.c`、`vocab_ui.c`、`vocab_audio.c`、生成的字体 | 只有这些代码调用 BSP、FreeRTOS、NVS 或 LVGL |

引擎是两层的边界。应用任务把原始按键事件和时间送入引擎，执行引擎返回的命令，并渲染引擎填写的视图模型。
系统级模拟（`tests/test_vocab_sim.c`）用脚本化事件和模拟设备驱动同一个引擎，因此设备与测试共用整个状态机的同一份实现。

### 2.3 任务与并发

| 上下文 | 优先级与栈 | 职责 |
| --- | --- | --- |
| 按键回调（共享的 `esp_timer` 任务） | 由 BSP 决定 | `on_key()` 先消耗深度睡眠按键防护，再以零超时把 `{key, event, time}` 放入长度为 16 的队列；队列满时丢弃新事件 |
| 应用任务 `vocab_app` | 5，6 KB | 引擎、命令执行、NVS、读电量、在 `bsp_lvgl_lock()` 下渲染；阻塞等待按键队列直到引擎的下一个截止时间 |
| 音频任务 `vocab_audio` | 6，3 KB 静态栈 | 启动后独占所有 `bsp_audio_*` 调用；请求队列长度 4；从不接触 LVGL 或 NVS |
| LVGL 移植任务 | 4 | 绘制画面；其他任务每次更新界面都持有 LVGL 锁 |

其他规则：按键回调从不阻塞；只有应用任务写 NVS，且从不在播放音频时写；每个 LVGL 对象只在 `vocab_ui_create()` 中创建一次，
之后只做显示、隐藏、改文字、改样式、移动或改尺寸；大块状态是静态存储，从不放在任务栈上；每张卡、每段声音都不分配内存。

### 2.4 一次按键的完整路径

1. BSP 回调调用 `vocab_app_post_key()`，以零超时放入队列。
2. 应用任务调用 `vocab_engine_key()`；`vocab_input_feed()` 应用规则 R1-R9，并向空闲时间线报告活动。
3. 被接受的意图进入 `vocab_session_handle()`：全局按键（长按 DOWN 调音量、长按 OK 暂停）或当前阶段的 `handle()`。
4. 阶段把命令追加到命令输出队列（outbox）。练习流程转换这些命令（定时器进入它自己的定时器表；无法播放的单词音频改为 WORD_PULSE），
   并在阶段报告结果时立即应用。
5. 应用任务按顺序执行命令，并在 LVGL 锁下渲染一次视图模型。

### 2.5 启动与内存

启动顺序：唤醒原因与按键防护、共享 I2C、显示与 LVGL（背光为 0）、应用任务（电量计、不自动擦除的 NVS、已存进度、音频包与音频任务、
全部控件、停在主页的引擎），最后是按键。背光只在显示主页的第一帧画完后才点亮（最多等待 500 毫秒），因此不会露出屏幕上电时的内容。

`CONFIG_LV_MEM_SIZE_KILOBYTES` 为 48：约 60 个带局部样式的控件常驻，LVGL 9 每次刷新还要从内存池分配绘制任务和字形缓冲，
24 KB 达不到“最大空闲块不小于 4 KB”的余量目标。应用在创建控件后，以及每种（屏幕，阶段）组合第一次出现时，记录
`lv_mem_monitor()`、空闲堆和栈的数据。近期构建的数据：静态 DRAM 占用略低于约 320 KB 的一半；应用镜像在嵌入本地音频包时约 1.15 MB，
嵌入空音频包时约 0.9 MB，factory 分区约 8 MB；七个字体约 142 KiB；本地音频包约 250 KB。

## 3. 引擎、练习流程与阶段契约

### 3.1 命令

每次调用纯逻辑核心时都会传入一个已清空、最多容纳 16 条有序命令的命令输出队列；溢出属于缺陷，测试断言它从不发生。

| 命令 | 发出者 | 应用任务的执行方式 |
| --- | --- | --- |
| `PLAY_WORD`、`PLAY_CUE`、`PLAY_CUE_THEN_WORD`、`STOP_AUDIO` | 阶段（经练习流程转换）、练习流程、引擎 | 音频任务请求 |
| `TIMER_START`、`TIMER_CANCEL` | 阶段 | 并入练习流程的定时器表，不会到达应用任务 |
| `NEW_EPOCH` | 阶段、练习流程、引擎 | 输入过滤器开始新的输入周期；应用任务清空按键队列，同时保留 PRESS/RELEASE 记录 |
| `SET_VOLUME` | 练习流程 | 音频任务音量：80、30 或 0 % |
| `SAVE` | 练习流程、引擎 | 经过音频闸门后保存（第 8.3 节） |
| `BACKLIGHT` | 引擎 | `bsp_display_backlight()`；为 0 时还暂停动画 |
| `READ_BATTERY` | 引擎 | `bsp_battery_soc()`，结果回报给引擎 |
| `DEEP_SLEEP` | 引擎 | 深度睡眠流程（第 7 节） |

### 3.2 练习流程

- 屏幕：BOOT、HOME、CARD、BANNER（突击检查引导、“太简单”确认与引导）、PAUSE、SUMMARY 和 BANK_ERROR。
  空词库或无效词库（缺字段、uid 重复或为 0、条目多于 `VOCAB_RECORDS_MAX`）显示 BANK_ERROR。
- 定时器：`STAGE` 和 `STAGE_AUX` 属于当前阶段，`SESSION` 用于横幅和小结锁定，`TOAST` 结束浮动提示。截止时间为绝对时间；
  `vocab_session_poll()` 按截止时间顺序触发到期的定时器，过早或过期的定时器事件被忽略，因此锁定总是持续完整时长。
- 锁定：阶段的 `locked` 标志加上横幅和小结的锁定构成 `vocab_session_locked()`，输入过滤器据此丢弃除长按 DOWN 以外的所有意图。
- 卡片流程：决定形式（第 5.6 节；熟练度为 0 时由练习流程挑选干扰项，没有可用干扰项就改用阶段 2）、把单词标记为见过、
  重置视图的阶段区域、显示卡片计数、开始输入周期、调用 `begin()`、转换其命令、有结果时应用结果，收到 DONE 后进入下一张卡或小结。
  阶段拒绝不可用的输入时，该卡被跳过，单词不会被标记为见过。
- 暂停：练习流程保存视图的阶段区域、取消阶段定时器、停止音频并显示暂停卡。继续时恢复该区域、开始新的输入周期并调用 `resume()`。
  离开时清空卡片队列和连续自评、停止音频、保存并显示主页，不推进练习计数。
- 音频替代：无法播放的 `PLAY_WORD`（静音、缺音频、音频不可用）改为 WORD_PULSE 动画；静音或音频不可用时丢弃提示音；
  `PLAY_CUE_THEN_WORD` 退化为提示音加闪亮动画。

### 3.3 阶段契约

`main/vocab_stage.h` 定义了练习流程与三个阶段模块之间唯一的接口：

```c
vocab_stage_result_t vocab_stageN_begin(vocab_stageN_t *st, const vocab_stage_input_t *in,
                                        vocab_ms_t now, vocab_view_t *view, vocab_outbox_t *out);
vocab_stage_result_t vocab_stageN_handle(vocab_stageN_t *st, const vocab_event_t *ev,
                                         vocab_ms_t now, vocab_view_t *view, vocab_outbox_t *out);
vocab_stage_result_t vocab_stageN_resume(vocab_stageN_t *st, vocab_ms_t now,
                                         vocab_view_t *view, vocab_outbox_t *out);
```

`vocab_stage_input_t` 包含词库、条目索引、用途（LEARN、TEST_LATER、SPOT_CHECK、TOO_EASY_CHECK）、形式、熟练度、
干扰项（阶段 1）、挖空例句正面标志（阶段 2）、是否允许“太简单”以及随机数生成器。返回值报告 RUNNING 或 DONE、
是否处于锁定窗口，以及结果确定时的结果。必须遵守的规则：

1. **生命周期。** 每张卡调用一次 `begin()`，每个事件调用一次 `handle()`；DONE 表示这张卡结束。暂停后的 `resume()`
   只重新设置当前状态需要的定时器，从不重播音频、也不报告结果。输入不可用时 `begin()` 返回 DONE 且不带结果。
2. **事件。** UP、DOWN、OK 的单击；仅 UP 的长按；两个阶段定时器的到时事件。长按 DOWN 和长按 OK 是全局按键，从不送到阶段；
   阶段报告锁定期间不会收到任何意图。
3. **结果。** 每张卡恰好报告一次，在结果确定的那次调用中报告。练习流程立即应用，因此即使孩子在随后的停留中暂停并离开，结果也会计入。
4. **定时器。** `STAGE` 和 `STAGE_AUX` 都是一次性定时器；重复效果（闪烁、跳动）是视图标志，不是定时器。
5. **锁定。** `locked` 只在需要忽略按键的窗口内为真：答题反馈、错题停留的锁定部分、阶段 3 的重试锁定和答对停留、
   阶段 2 的确认与“忘了”回应。阶段 2 正面的最短时间不是锁定，“太简单”和暂停仍然可用。
6. **输入周期。** 由按键或定时器引起的每次状态变化都追加 `NEW_EPOCH`；`begin()` 和 `resume()` 从不追加，因为这些周期由练习流程开始。
7. **音频。** 阶段只请求声音，从不检查静音或音频是否存在。
8. **视图。** 阶段只写阶段区域，中文文字取自 `vocab_strings.h`，并且从不显示拼错的英文（第 11 节）。

### 3.4 阶段时长

| 窗口 | 常量 | 值 |
| --- | --- | --- |
| 阶段 1 与检查卡答对反馈 | `VOCAB_CORRECT_FEEDBACK_MS` | 600 毫秒 |
| 错题停留锁定（阶段 1 答错、阶段 3 揭示） | `VOCAB_ERROR_HOLD_MS` | 1500 毫秒 |
| 阶段 2 正面最短时间（不是锁定） | `VOCAB_S2_FRONT_MIN_MS` | 1000 毫秒 |

| 阶段 2“忘了”回应 | `VOCAB_S2_FORGOT_ACK_MS` | 600 毫秒 |
| 阶段 3 重试锁定 | `VOCAB_S3_RETRY_LOCK_MS` | 600 毫秒 |
| 阶段 3 答对停留 | `VOCAB_SUCCESS_HOLD_MS` | 1200 毫秒 |

## 4. 视图模型与渲染器

- `vocab_view_t`（`main/vocab_view.h`）描述整个屏幕：屏幕类型、状态栏（卡片计数或等级、电量百分比、音量与电池图标）、徽标、
  卡片区（单词、音标、意思、挖空例句、例句、阶段 3 意思、单词骨架、提示语、横幅）、两个选项面板、提示栏与浮动提示、主页、小结、
  宠物、经验条和动画计数器。文字标签为 `{visible, color, text[48]}`。
- 归属：阶段写阶段区域（除横幅外的卡片字段、两个面板、徽标、提示类型，以及晃动、跳动、确认计数器）；其余部分归练习流程
  （横幅、状态栏、浮动提示、解析后的提示文字、主页、小结、宠物、经验条、闪亮与宠物计数器）。暂停卡会原样恢复阶段区域。
- 一次性动画是只增不减的计数器（`shake_seq`、`pulse_seq`、`nudge_seq[2]`、`confirm_seq[2]`、`pet_seq`）；
  重复效果是标志（`skeleton.blink`、`panel.nudge_repeat`）。渲染器在计数器变化时启动动画，因此主机测试不需要 LVGL 就能检查动画是否被请求。
- `vocab_view_resolve()` 把提示类型转换成文字。重听提示根据当前单词音频能否播放显示“● 再听一遍”或“● 再看一遍”；
  浮动提示会替换提示栏文字 1.2 秒。在主页上，开始提示行（“按 ● 开始挑战”）承担提示栏的角色：显示浮动提示期间练习流程隐藏开始提示行，
  浮动提示结束后它重新出现。
- 渲染器（`main/vocab_ui.c`）：每个控件在启动时只创建一次，之后只做显示、隐藏、改文字、改样式、移动或改尺寸；
  不使用缩放或旋转变换、分层不透明度或阴影（它们需要从 LVGL 内存池申请绘制层）；每个标签都显式设置字体；没有变化的值不重复设置；
  控件隐藏、熄屏和深度睡眠前都会停止其动画。
- 布局规则（`main/vocab_layout.h`，纯逻辑，有主机测试）：
  - 字号：文字宽度不超过 196 px 用 36 px，否则不超过 196 px 时用 28 px，再否则用 22 px 并在 200 px 处换行、最多两行
    （超过两行属于词库错误）。设备上用真实字体测量（`lv_text_get_size`）。
  - 阶段 3 单词骨架：按完整的正确单词决定字号，只有带空格框的整行宽于卡片 216 px 的内宽时才缩小；空格框宽度为
    `max(width(right), width(wrong)) + 8` px。几何尺寸既不取决于哪个字母块正确，也不取决于空格是否已填，因此框宽不会泄露答案，
    答对时整行也不会位移。
  - 阶段 2 背面：单词、意思和可能占两行的例句在卡片内依次排开，互不重叠。
  - 所有布局都读取字体的真实行高，而不是“字号 + n”。
- 屏幕几何：背景 0x121826；卡片位于 (10, 34)，220 x 120；选项面板位于 y 160 和 y 224，各 220 x 56；提示栏位于 y 290。
  由于圆角遮罩，y 小于 30 或大于 290 的文字限制在 x 16-224 之内。

## 5. 学习模型

### 5.1 熟练度与复习间隔

| 熟练度 | 名称 | 常规卡片 | 升级到该级时的间隔（练习组数） |
| --- | --- | --- | --- |
| 0 | 新词或重学 | 阶段 1 | 无：失败总是 due = T + 1 |
| 1 | 见过 | 阶段 2，单词正面 | 1 |
| 2 | 熟悉 | 阶段 2，条件允许时用挖空例句正面 | 2 |
| 3 | 能回想 | 阶段 3，退回阶段 2 | 5 |
| 4 | 能拼写 | 阶段 3，退回阶段 2 | 10 |
| 5 | 已掌握 | 阶段 3，退回阶段 2 | 20；通过“太简单”检查后为 30 |

每个词在内存中有一条与词库平行的 8 字节记录：uid、到期计数、熟练度、标志（见过、曾经掌握）和一个只用于统计的饱和出错计数。

### 5.2 练习计数

设备没有实时时钟，因此 `tick`（16 位，存于 NVS）记录已完成的练习组数。进行中的一组使用 T = tick；一组到达小结时，
在小结保存之前 tick 加一。中途放弃的一组（暂停后回主页、深度睡眠、断电）保留已应用的结果，但不推进 tick。
一个词“到期”指它已经见过且 `due <= T`；逾期程度为 `T - due`。到期计算在 65535 处饱和，按每天三组计算可用 50 年以上。

### 5.3 结果

`m` 为卡片前的熟练度，`m'` 为卡片后的熟练度；升级时设置 `due = T + INTERVAL[m']`。客观题卡片由第一次按键决定结果。

| 编号 | 用途与形式 | 作答 | 之后的熟练度 | 之后的到期 | 附带效果 |
| --- | --- | --- | --- | --- | --- |
| O1 | LEARN，阶段 1 | 第一次就答对 | 1 | T+1 | 首次答对经验 |
| O2 | LEARN，阶段 1 | 第一次答错 | 0 | T+1 | 之前见过时计一次出错；错题停留 |
| O3 | LEARN，阶段 2 | 认识 | min(m+1, 5) | T+INTERVAL[m'] | 把自评连同自评前的状态压入连续自评 |
| O4 | LEARN，阶段 2 | 忘了 | min(m, 1) | T+1 | 计一次出错；清空连续自评；插入 TEST_LATER |
| O5 | TEST_LATER，阶段 1 | 第一次就答对 | 不变 | 不变 | 首次答对经验 |
| O6 | TEST_LATER，阶段 1 | 第一次答错 | 0 | T+1 | 计一次出错；错题停留 |
| O7 | LEARN，阶段 3 | 第一次就答对 | min(m+1, 5) | T+INTERVAL[m'] | 首次答对经验 |
| O8 | LEARN，阶段 3 | 第二次答对 | 不变 | T+1 | 无 |
| O9 | LEARN，阶段 3 | 第二次答错（揭示） | 2 | T+1 | 计一次出错；揭示停留 |
| O10 | SPOT_CHECK，阶段 1 或 3 | 第一次就答对 | 不变 | 不变 | 首次答对经验；自评有效；清空连续自评 |
| O11 | SPOT_CHECK，阶段 1 或 3 | 第一次答错 | 被查词：min(自评前 m, 1)；其他自评：恢复自评前 m | 被查词：T+1；其他：min(自评前 due, T+1) | 被查词计一次出错；清空连续自评；错题停留 |
| O12 | LEARN，阶段 1 题目或阶段 2 正面 | 长按 UP（太简单） | 不变 | 不变 | 当前卡结束；插入 TOO_EASY_CHECK |
| O13 | TOO_EASY_CHECK，阶段 3 或 1 | 第一次就答对 | 5 | T+30 | 首次答对经验 |
| O14 | TOO_EASY_CHECK，阶段 3 或 1 | 第一次答错 | min(m, 1) | T+1 | 计一次出错；错题停留 |

首次达到熟练度 5 时设置“曾经掌握”标志，并计入掌握奖励。单词在卡片开始时被标记为见过，因此 O2 只在这张卡之前就见过该词时才计出错。
O11 还会恢复每个被作废自评的“曾经掌握”标志：被作废的自评同时失去掌握奖励。阶段 1 答错后熟练度保持 0，而不是在本组内重新排入，
以保持每组简短；自评“认识”不得经验，因为没有经过验证。

### 5.4 选词规则

`vocab_srs_compose()` 是词库、记录、T 和随机数生成器的纯函数：

1. D = 到期的词，按逾期程度降序，其次熟练度低者优先，再次 uid 小者优先。
2. N = 未见过的词，按词库顺序；词库顺序就是课程顺序。
3. E = 见过但尚未到期的词，按到期计数升序，其次熟练度低者优先，再次 uid 小者优先。
4. `n_new = min(|N|, MAX_NEW_PER_SESSION, max(MIN_NEW_PER_SESSION, SESSION_WORDS - |D|))`，
   其中 `SESSION_WORDS` 为 5、`MAX_NEW_PER_SESSION` 为 3、`MIN_NEW_PER_SESSION` 为 1。
5. `n_rev = min(|D|, SESSION_WORDS - n_new)`。
6. 取 D[0, n_rev) 和 N[0, n_new)；剩余位置先从 E 补，再从新词上限之外的 N 补。每组词数 = min(5, 词库大小)。
7. 打乱所选的词（用注入的随机数生成器做 Fisher-Yates 洗牌）。

新设备得到五个新词；七个到期词时取逾期最久的四个加一个新词；两个到期词时取这两个加三个新词；
既没有到期词也没有新词时，复习最快到期的词，保证孩子随时都能练习。

### 5.5 卡片队列与插入卡

- 一张卡包含：词库索引、用途、显示时才决定的形式、干扰项、是否已产生过插入卡、突击检查槽位和自评前熟练度；正确一侧由阶段抽取。
  TEST_LATER 和 TOO_EASY_CHECK 卡插入在 `min(cur + 1 + INSERT_GAP, len)`，其中 `INSERT_GAP` 为 2；SPOT_CHECK 卡插入在 `cur + 1`。
- 每个基础词每组最多产生一张插入卡，插入卡本身不再产生插入卡，因此队列上限为 `MAX_CARDS` = 10。
  状态栏显示 `n/N`；插入卡片的同一次调用就会刷新 N，因此新的总数在下一帧就会出现。

### 5.6 阶段分配

| 卡片 | 形式 |
| --- | --- |
| LEARN，熟练度 0 | 带干扰项的阶段 1；没有有效干扰项时为阶段 2 单词正面 |
| LEARN，熟练度 1 | 阶段 2，单词正面 |
| LEARN，熟练度 2 | 阶段 2：条目有 `example_cloze` 且单词音频能播放时用挖空例句正面，否则用单词正面 |
| LEARN，熟练度 3-5 | 条目有填空数据时为阶段 3，否则为阶段 2（正面规则同熟练度 2） |
| TEST_LATER | 阶段 1，尽量避开该词之前用过的干扰项 |
| SPOT_CHECK | 被查词有填空数据且自评前熟练度不低于 2 时为阶段 3，否则为阶段 1 |
| TOO_EASY_CHECK | 条目有填空数据时为阶段 3，否则为阶段 1 |

无法出题的检查卡（既无填空数据也无干扰项）会被跳过；跳过突击检查时清空连续自评，自评保持有效。

阶段 1 干扰项（`vocab_lure_pick()`）：另一个类别不同、意思不同、且两个意思互不包含的条目（例如“书”和“打开你的书”）；
优先同类（单词或短语）；只有别无选择时才允许同一类别；用随机数均匀选择；正确一侧由一个随机位决定。

### 5.7 突击检查与“太简单”

- 连续自评记录自上次突击检查、“忘了”或本组开始以来阶段 2 的“认识”自评。中间的阶段 1、阶段 3 卡片不会清空它；
  暂停后回主页时丢弃它（自评保持有效）；到小结时仍在其中的自评保持有效。
- 自评达到 `SPOT_CHECK_THRESHOLD` = 3 次时，立即插入一张 SPOT_CHECK 卡作为下一张，先显示 800 毫秒横幅。
  被查词由随机数在自评过的词中抽取，但不包括最后一个（它的意思刚刚还在屏幕上）。答对（O10）：自评有效。答错（O11）：整轮自评回滚。
- “太简单”（长按 UP）只在 LEARN 卡的阶段 1 题目或阶段 2 正面提供，并且要求队列有空位、该词本组尚未产生插入卡、
  检查卡能够出题（有填空数据或干扰项）。当前卡在 800 毫秒确认后结束，检查卡在两张卡之后出现，因为完整拼写刚刚还在屏幕上。
  侥幸猜对（50 %）会在下一次复习时被发现。

### 5.8 经验、等级与宠物

- 经验只在小结时发放：每完成一组 5 点，客观题每次第一次就答对再加 1 点（O1、O5、O7、O10、O13），每个首次达到熟练度 5 的词再加 2 点。
  经验是饱和的 32 位数值。
- 等级门槛：Lv1 0、Lv2 30、Lv3 90、Lv4 180、Lv5 300、Lv6 450、Lv7 630、Lv8 840、Lv9 1080、Lv10 1350（最高）。
  称号依次为：单词新手、单词学徒、单词探险家、单词小勇士、单词小达人、单词高手、单词明星、单词冠军、单词大师、单词之王
  （`VOCAB_STR_TITLES_INIT`）。
- 宠物阶段：蛋（Lv1）、幼崽（Lv2-3）、小孩（Lv4-6）、成体（Lv7-9）、戴王冠的成体（Lv10）。宠物由 80 x 80 方框内最多 18 个普通
  LVGL 矩形绘制：主页上浮动和眨眼，小结时进食和跳跃，升级时换色并跳三下。它没有饥饿、衰退或难过状态：设备没有时钟，宠物也不应让孩子焦虑。

## 6. 输入防护

BSP 上报 PRESS、CLICK（松开后约 180 毫秒、排除双击之后）、DOUBLE、LONG（500 毫秒时一次）和 RELEASE。
按键驱动把同一个键松开后 180 毫秒（`BSP_BTN_SHORT_PRESS_MS`）内开始的下一次按压与前一次合并为一个 DOUBLE，
在第二次松开后约 185 毫秒送达；连续快速按三次或更多次则完全不产生单击，因为 BSP 只注册了单击和双击。
只有 CLICK、DOUBLE 和 LONG 表达意图。

按压序列：过滤器为每个键跟踪可能被驱动合并上报为一个 DOUBLE 的那些按压。同一个键 RELEASE 之后
`VOCAB_DOUBLE_WINDOW_MS`（220 毫秒：`VOCAB_BTN_SHORT_PRESS_MS` 180 加 40 毫秒余量；前者是 `BSP_BTN_SHORT_PRESS_MS` 的镜像，
由 `vocab_app.c` 中的静态断言保证两者相等）内开始的 PRESS 延续该序列，除非前一次按压产生了 LONG，或者某个 CLICK、DOUBLE 或 LONG
已经结束了这个序列（包括被清空丢弃的事件）。单独的 CLICK 和 LONG 按它自己的那次按压判断；DOUBLE 按整个序列判断。
`vocab_input` 按顺序应用以下规则：

| 规则 | 行为 | 常量 |
| --- | --- | --- |
| R1 归一化 | DOUBLE 视为一次 CLICK；PRESS 和 RELEASE 只更新记录并计为活动 | - |
| R2 只唤醒 | 熄屏时第一次 PRESS 只负责唤醒；直到这次按压松开后再过一段尾随时间，所有 CLICK 和 LONG 都被丢弃。唤醒键延续其序列的第二次按压会让尾随时间从它自己的 RELEASE 重新开始，因此唤醒时的双击整体被吞掉。丢失 RELEASE 时有安全解除 | `VOCAB_WAKE_TAIL_MS` 400、`VOCAB_WAKE_GUARD_MAX_MS` 10000 |
| R3 输入周期 | PRESS 发生在当前周期开始之前、或没有记录到 PRESS 的意图被丢弃；DOUBLE 以其第一次按压的开始时间为准 | - |
| R4 冷却 | 周期开始后冷却时间内按下的 UP、DOWN 单击被丢弃（按按下时间计，因为 CLICK 在松开后约 180 毫秒才到达）；DOUBLE 以第一次按压为准 | `VOCAB_CARD_COOLDOWN_MS` 250 |
| R5 锁定 | 练习流程报告锁定时只放行长按 DOWN | - |
| R6 跨键幻影 | 另一个键仍按着时开始的按压所产生的意图被丢弃；DOUBLE 中任何一次按压是这样开始的，整个 DOUBLE 都被丢弃；过期的按住标志自动失效 | `VOCAB_WAKE_GUARD_MAX_MS` 10000 |
| R7 过短按压 | 按压时长短于下限的 CLICK 被丢弃；DOUBLE 只要有一次按压达到下限就放行 | `VOCAB_MIN_PRESS_MS` 30 |
| R8 长按后回弹 | 同一个键长按松开后很快又开始的按压视为抖动，其 CLICK 和 LONG 被丢弃；以这种方式开始序列的 DOUBLE 也被丢弃 | `VOCAB_LONG_REJOIN_MS` 120 |
| R9 每个周期只变一次 | 每个改变卡片或卡面的意图都会开始新的周期（`NEW_EPOCH`） | - |

按键队列容纳 16 个原始事件（`VOCAB_INPUT_QUEUE_DEPTH`）。按键唤醒深度睡眠后，`main.c` 启用 `key_guard`，
使按键驱动认为“已经按着”的唤醒键不会产生动作；`on_key()` 在检查输入就绪之前先消耗这个防护，这是
`tests/test_key_wake_contract.py` 的要求。R6 针对的是共用分压线上已有记录的幻影按键
（[ADC 分压按键长按误读](../reference/shinku-chen/adc-ladder-keypad-long-press-misread.zh_CN.md)）；
如果真机测试仍出现跨键事件，下一步是在 BSP 中加入按键身份锁，这属于板级改动。

## 7. 电源与深度睡眠

| 阶段 | 触发条件（距任意键最后一次 PRESS） | 动作 |
| --- | --- | --- |
| 活跃 | - | 背光 `VOCAB_BACKLIGHT_ON` 80 % |
| 变暗 | `VOCAB_IDLE_DIM_MS` 20000 | 背光 `VOCAB_BACKLIGHT_DIM` 20 %；按键照常工作 |
| 熄屏 | `VOCAB_IDLE_OFF_MS` 30000 | 停止音频、经过音频闸门保存、背光 0、暂停动画；保持状态 |
| 睡眠 | 熄屏后 `VOCAB_DEEP_SLEEP_AFTER_OFF_MS` 120000（共 150 秒） | 有变化时保存，然后执行深度睡眠流程 |

任何 PRESS 都会重新开始这条时间线，即使它的意图被丢弃；卡片的定时行为不算活动。从熄屏唤醒会恢复背光、读取电量，
并在同一屏幕上开始新的输入周期。

深度睡眠流程与 `main/demo_low_power.c` 一致，由 `tests/test_vocab_contract.py` 检查顺序：

1. 有键按着（`bsp_button_read_mv()` 低于 `BSP_BTN_MV_RELEASED_MIN`）时拒绝：保持熄屏，`VOCAB_SLEEP_RETRY_MS`（5 秒）后重试。
2. `vocab_audio_shutdown(1000 ms)`：音频任务确认后退出；超时则重启芯片而不是睡眠。
3. `bsp_button_prepare_deep_sleep()` 把按键引脚交还为数字输入（失败则重启），然后启用 GPIO0 低电平唤醒；不使用定时唤醒。
4. `bsp_battery_sleep()`、`bsp_audio_sleep()`、`bsp_audio_prepare_deep_sleep()`、`bsp_i2c_prepare_deep_sleep()`。
5. 获取 LVGL 锁（本次运行不再释放），暂停动画，`bsp_display_prepare_deep_sleep()`。
6. `esp_deep_sleep_start()`；万一返回则重启芯片。

唤醒即重启：显示主页，唤醒的那次按压被吞掉。NVS 保留进度、tick、经验、音量和统计；进行中的卡片队列丢失，但已应用的结果在熄屏时已保存。
不使用浅睡眠：LVGL 刷新和 ADC 按键轮询会不断唤醒芯片。应用在启动、从熄屏唤醒时以及每隔 `VOCAB_BATTERY_POLL_MS`（30 秒）读取电量；
图标阈值为 80、55、30、10 %，不高于 15 % 时为红色，不高于 10 % 时主页提示，不高于 5 % 时每张卡结束都保存。

## 8. 持久化

### 8.1 键与二进制格式

NVS 命名空间 `vocab`；显式小端序列化（不直接复制结构体），CRC-32/IEEE（反射，初值与最终异或值均为 0xFFFFFFFF）。

`meta`（40 字节）：

| 偏移 | 长度 | 字段 |
| --- | --- | --- |
| 0 | 2 | 魔数 0x564D |
| 2 | 1 | 格式版本（1） |
| 3 | 1 | 音量索引（0 = 80 %，1 = 30 %，2 = 静音） |
| 4 | 2 | 练习计数 |
| 6 | 2 | 进度块数量 |
| 8 | 4 | 经验 |
| 12 | 4 | 词库指纹：对升序排列的 uid（每个 2 字节）计算 FNV-1a 32 |
| 16 | 4 | 累计客观题作答数 |
| 20 | 4 | 累计第一次就答对数 |
| 24 | 12 | 保留（0） |
| 36 | 4 | 字节 0-35 的 CRC-32 |

进度块 `p00`、`p01`……按 uid 升序保存记录，每块 64 条（第 i 块保存第 [64 i, 64 i + 64) 条）：8 字节块头（魔数 0x5650、版本 1、
记录数、写入时的 tick、块序号），随后每条记录 6 字节（uid、到期、状态字节：位 0-2 为熟练度，位 3 为见过，位 4 为曾经掌握；出错次数），
最后是对前面所有字节计算的 CRC-32。

### 8.2 加载与迁移

1. 先读 `meta`，再读进度块键 `p00`-`p31`；逐个校验魔数、版本、长度和 CRC。
2. 按 uid 把记录匹配到编译进固件的词库：未知 uid 丢弃，没有记录的词库 uid 从头开始，重复 uid 保留第一条，熟练度大于 5 时截为 5，
   到期晚于 `tick + 2 x INTERVAL[5]` 时重置为 `tick + INTERVAL[m]`。
3. 词库指纹变化或格式版本较旧时全部标记为待写：下次保存会重写 `meta` 和所有进度块，并删除多余的进度块键。
4. `meta` 或任一进度块带有更新的未知格式版本时切换到易失模式：永远不覆盖任何数据。

### 8.3 保存点与保存闸门

- 保存点：小结（音频停止之后、欢呼提示音之前）、熄屏、暂停后回主页、深度睡眠前，以及电量不高于 5 % 时每张卡结束。
  音量变化只把 `meta` 标记为已变化。
- 只写入自上次成功保存以来内容有变化的进度块，然后写 `meta`，再删除多余的键，最后一次 `nvs_commit`。
  如果在写进度块与写 `meta` 之间断电，数据仍然一致，因为到期计数相对于未变化的 tick。
- 保存闸门：保存前先请求 STOP，再每 10 毫秒检查一次音频任务的空闲标志，最多等待 `VOCAB_SAVE_AUDIO_WAIT_MS`（2000 毫秒）；
  音频仍忙时不写任何内容，推迟到下一个保存点。所有音频请求都由应用任务自己发出，因此保存期间不会开始播放声音。
  从不在 LVGL 任务或按键回调中写 NVS。

### 8.4 故障处理

应用永远不会“变砖”，也从不自动擦除存储：

- `nvs_flash_init()` 失败（包括没有空闲页和发现新 NVS 版本）：进入易失模式（只用内存），主页显示提示；恢复方法是重新烧录合并镜像，
  它可能重写 NVS 区域。
- `nvs_open`、读或写出错：记录日志；保留内存中的状态和变化，在下一个保存点重试；保存成功之前主页一直显示提示。任何 NVS 路径都不使用
  `ESP_ERROR_CHECK` 或 abort。
- 损坏的进度块只让它自己包含的词从头开始。`meta` 损坏时使用默认值（经验 0、音量 80 %），`tick` 取有效进度块写入时的最大 tick，
  使到期计数仍有意义。

### 8.5 NVS 容量

默认分区表给 NVS 24 KB（0x6000）：6 页、每页 126 个条目，保留一页空闲，可用 630 个条目。b 字节的数据块占 2 + ceil(b / 32) 个条目，
另加一个命名空间条目。以下数据来自 `vocab_nvs_budget()`：

| 词数 | 进度块 | 条目 | 占 24 KB | 占 48 KB（0xC000） |
| --- | --- | --- | --- | --- |
| 48（测试词库） | 1 | 17 | 3 % | 1 % |
| 256（`VOCAB_RECORDS_MAX`） | 4 | 65 | 10 % | 5 % |
| 1000 | 16 | 240 | 38 % | 17 % |
| 1200 | 19 | 287 | 46 % | 21 % |
| 2000 | 32 | 476 | 76 %，判定为过紧 | 34 % |

模型把占用超过一半可用条目判定为过紧，因为换词库后重写所有进度块需要为新写入的副本留出余量。词库超过约 1200 个词之前，
应把 NVS 扩大到至少 48 KB；这项分区表改动必须通过固件门禁，并且会重置已存进度。内存开销为每个词 8 字节。

## 9. 音频流水线

### 9.1 离线生成（仅限本地）

单词音频仅供测试且属于私有内容（第 12.1 节）：它们在 Windows 电脑上生成，不进入 Git，只能通过本地构建进入固件。
仓库只提交一个空音频包。

| 步骤 | 工具 | 输出 |
| --- | --- | --- |
| 朗读每条词库文本 | `tools/vocab_audio/gen_tts.ps1`（Windows PowerShell 5.1、System.Speech、语音 Microsoft Zira Desktop、语速 -2、音量 100、16 kHz 16 位单声道；缺少该语音时失败，从不替换为其他语音） | 每个 uid 一个 WAV，放在被 Git 忽略的缓存目录 `build/vocab_tts/`，另有 `tts_list.tsv` 和 `tts_info.txt`（语音、引擎文件、Windows 版本） |
| 裁剪、归一化、编码 | `tools/vocab_audio/build_clips.py build`（2.0 版，Python 标准库，整数运算） | 被 Git 忽略的本地音频包 `assets/audio/vocab_test_clips.bin` 和清单 `assets/audio/vocab_test_clips.csv`，以及提交到仓库的空音频包 `assets/audio/vocab_clips_empty.bin` |
| 只重写空音频包 | `tools/vocab_audio/build_clips.py empty` | `assets/audio/vocab_clips_empty.bin` |
| 检查 | `tools/vocab_audio/build_clips.py --check`（不需要 Windows；由 `tests/test_vocab_clips.py` 运行） | 总是检查空音频包；存在本地音频包时还检查其结构、与清单的一致性、每个词库 uid 恰好一段音频、时长、响度和静音 |

`--clips-dir` 或环境变量 `VOCAB_CLIPS_DIR` 可以为 Python 工具和测试中的本地音频包和清单指定其他目录（测试用一个没有音频包的目录来模拟 CI）；
固件构建总是在 `assets/audio/` 中查找。

处理：以 10 毫秒为帧裁掉首尾低于 -40 dBFS 的部分，语音前保留 30 毫秒、后保留 60 毫秒；8 毫秒淡入淡出；以恒定增益把语音 RMS 调到 -18 dBFS，
并用 -1 dBFS 的前瞻峰值限制器（cat、tiger、bus、car、bike、foot 六段用到了它，记录在清单的 `limiter_db` 列）；单词最长 1.6 秒，短语最长 2.5 秒。
在同一台机器、同一语音上重新运行会得到完全相同的字节。

### 9.2 音频包格式、选择与查找

- 音频包自带描述（格式“VCLP”，版本 1，小端）：24 字节头 {魔数 "VCLP"、u16 版本、u16 索引项大小 16、u32 音频段数、u32 音频包大小、
  u32 对头部前 16 字节和索引计算的 CRC-32、u32 保留}，随后每段音频一个 16 字节索引项 {u16 uid、u16 0、u32 偏移、u32 n_samples、u32 n_bytes}，
  按 uid 排序，最后是位于 4 字节对齐偏移处、以零填充的各段音频。空音频包就是音频段数为 0 的 24 字节头。
- 每段音频：4 字节头 {int16 小端初始预测值、uint8 步长索引 0-88、0}，随后是 4 位 IMA-ADPCM 码，低半字节在前，每个码对应一个 PCM 样本。
- `main/vocab_clips.c` 是手写代码（不存在生成的索引）。它校验整个音频包（魔数、版本、大小、CRC、顺序、对齐、重叠、边界和每段音频的头），
  格式错误或来路不明的音频包被整体拒绝，之后的表现与空音频包相同。有效的索引被复制到最多 256 项的静态表中（约 4 KB 内存），
  `vocab_clip_find(uid)` 在其中二分查找，没有音频的 uid 返回 NULL。
- `main/CMakeLists.txt` 以符号 `_binary_vocab_clips_bin_start` 和 `_end` 嵌入恰好一个音频包：本地音频包存在且未设置 `VOCAB_NO_CLIPS` 时
  嵌入本地音频包，否则嵌入提交到仓库的空音频包。配置日志会报告选择结果（`Word Buddy clips: embedding ...`）。选择在配置阶段做出，
  因此新增或删除本地音频包后需要使用新的构建目录或运行 `idf.py reconfigure`；`-D VOCAB_NO_CLIPS=1` 会一直留在该构建目录的 CMake 缓存中，
  直到把它设为 0 或删除。
- 启动时 `vocab_audio_start()` 先安装嵌入的音频包，再启动编解码器，因此即使音频故障，查找也能工作。被拒绝的音频包在日志中记为错误，
  空音频包记为警告（单词使用视觉替代）。
- C 解码器会钳位预测值和索引，并与 `build_clips.py` 中的 Python 参考解码器逐位一致（`tests/test_vocab_adpcm.c`）。
- 本地测试音频包有 48 段（约 32 秒，约 250 KB），在 600 KB 预算之内。

### 9.3 音频任务

- `vocab_audio_start()` 随后依次执行 `bsp_audio_init()`、`bsp_audio_set_format(16000, 16, 1)`、设置音量并创建音频任务
  （优先级 6、3 KB 静态栈、请求队列长度 4）。应用任务发请求从不阻塞；队列满时丢弃该请求。
- 音频任务用静态缓冲区按 256 样本（16 毫秒）一块渲染，并用阻塞的 `bsp_audio_write()` 写出，节奏由 I2S DMA（约 90 毫秒）决定。
  新的 PLAY 或 STOP 在下一个块边界处经 4 毫秒淡出后打断当前声音。
- 声音结束或停止后，音频任务先写入约 96 毫秒静音再报告空闲，这样 NVS 写入使 Flash 缓存停顿时，DMA 环形缓冲里只有静音。
- 音量为 0 时完全不写 I2S，静音期间拒绝播放请求。写入出错会停止当前声音并记录日志；音频任务继续处理请求。
- 深度睡眠前，`vocab_audio_shutdown()` 停止播放并等待音频任务的确认。

### 9.4 提示音

运行时用整数运算合成（256 项 Q15 正弦表，不依赖 libm），起音和释音各 5 毫秒；不存储任何提示音文件。

| 提示音 | 声音 | 峰值 | 用途 |
| --- | --- | --- | --- |
| CORRECT | 1319 Hz 70 ms + 1760 Hz 110 ms | -9 dBFS | 阶段 1 与检查卡答对 |
| WRONG | 392 Hz 90 ms + 330 Hz 150 ms | -6 dBFS | 答错，在单词读音之前 |
| FLIP | 600 -> 1200 Hz 滑音，60 ms | -12 dBFS | 阶段 2 翻面 |
| TICK | 1000 Hz，40 ms | -12 dBFS | 自评确认、音量变化 |
| CHEER | 1047、1319、1568 Hz 各 80 ms + 2093 Hz 160 ms | -9 dBFS | 阶段 3 答对、小结 |
| LEVEL_UP | 1047、1319、1568、2093、1568 Hz 各 80 ms + 2093 Hz 300 ms | -9 dBFS | 小结时升级，代替 CHEER |

频繁出现的明亮提示音较轻，以免盖过单词读音；低音的 WRONG 使用完整的 -6 dBFS 余量。

### 9.5 何时播放声音

| 时刻 | 声音 |
| --- | --- |
| 卡片出现（阶段 1、阶段 2 正面、阶段 3、每张插入卡） | 单词读音 |
| 阶段 2 翻面 | FLIP，然后单词读音 |
| 单击 OK（阶段 1、阶段 2 背面、阶段 3、错题停留等待中） | 单词读音 |
| 答错（阶段 1、阶段 3 答错、揭示） | WRONG，然后单词读音 |
| 答对（阶段 1、检查卡） | CORRECT |
| 阶段 3 答对 | CHEER，然后单词读音 |
| 阶段 2“认识”或“忘了”、音量变化 | TICK（切换到静音时不播放） |
| 小结，保存之后 | CHEER 或 LEVEL_UP |
| 暂停卡、回到主页（从暂停卡或小结）、熄屏、深度睡眠 | 停止播放 |

静音、缺少音频或音频故障时，每个单词读音都改为 WORD_PULSE：可见的英文元素（单词、挖空例句或单词骨架）变成 0xFDE047 并出现 4 px 下划线，
持续 600 毫秒，重听提示变为“● 再看一遍”。提示音不需要替代，因为每个提示音都有对应的视觉变化。如果 `bsp_audio_init()` 失败，
音量图标显示暗色的静音符号，长按 DOWN 显示“声音不可用”。

使用空音频包的构建（从仓库构建的所有固件，包括 CI）是缺少音频的一个特例：每个单词都使用 WORD_PULSE 和“● 再看一遍”，
从不选择阶段 2 的挖空例句正面（它需要单词音频，第 5.6 节），提示音、音量控制和音量图标照常工作。

七个生成字体合计约 142 KiB，预算为 220 KB。全部为 4 bpp、无压缩，没有后备字体链：缺字时 LVGL 会画出占位方框，
而覆盖检查保证这种情况不会被发布。

### 10.2 生成与校验

- `tools/vocab_fonts.py generate --fonts-src <dir>` 用 Pillow/FreeType 栅格化每个角色，写出 LVGL 9 `fmt_txt` C 源文件：PLAIN 4 bpp、
  高半字节在前、每个字形字节对齐、ASCII 连续段用 FORMAT0_TINY、其余用 SPARSE_TINY、不含字距调整，行高和基线取自子集的实际墨迹范围。
  它会重新解析每个生成文件，按 LVGL 自己的公式放置每个解码后的字形，并与栅格化结果逐像素比较；任何不一致都会失败。
- 从不发布 `lv_font_conv` 生成的位图：已观察到 1.5.3 版在当前 Node.js 下写出损坏的字形位图
  （[LVGL 中文字体子集](../reference/shinku-chen/lvgl-cjk-font-subsets.zh_CN.md)）。
- 源字体以 SHA-256 固定版本且从不提交；生成的子集使用中性名称（`vocab_font_*`），不使用任何保留字体名。

### 10.3 字符清单与覆盖检查

字符清单从源文件重新生成：`main/main.c` 和 `main/vocab_*.{c,h}` 中的全部字符串字面量（不含注释）、词库的 `zh`、`ipa` 和英文字段、
七个全角标点 ，。！？：（）、U+00B7、U+2026 以及按键符号 ▲ ▼ ●。目前为 207 个汉字加 12 个标点与符号码位（共 219 个），以及 16 个音标符号。
`python3 tools/vocab_fonts.py --check`（只用标准库，由静态门禁中的 `tests/test_vocab_fonts.py` 运行）在以下情况失败：显示某码位的角色缺少该码位、
字体结构无效、F_IPA 区分不了 U+0061 和 U+0251、F_EN_XS 失去单层 a，或生成文件与记录的生成结果不一致；
反向自测会注入未覆盖的字符和互换的 a 字形，并要求检查失败。字符清单、生成器版本和每个字体的哈希记录在
`assets/fonts/vocab/vocab_fonts_inventory.json`。

### 10.4 音标字体角色

Andika 把 U+0061 a 画得和 U+0251 ɑ 一样，于是 bike 中的 /aɪ/ 和 car 中的 /ɑː/ 会看起来相同。因此 F_IPA 把 U+0061 映射为 Andika 的双层 a
（OpenType 样式集 ss13），并且只用于音标行。所有面向孩子的英文角色（包括 F_EN_XS）都保留 Andika 的单层 a，也就是孩子学写的字形。

## 11. 英文安全不变式

单词伙伴从不显示拼错的英文单词：看到错误拼写可能会让孩子记住它。任何视图模型中允许出现的英文只有：

- 条目的 `text`、`example`、`example_cloze`（用 `____`，总是四个下划线，不泄露长度）和音标；
- 选项面板中单独出现的填空字母块；
- 阶段 3 单词骨架：条目文字的前缀和后缀，以及为空或填入正确字母块的空格。错误字母块只存在于 `skeleton.other` 中，用于测量尺寸，从不绘制。

保障机制：

- 阶段 1 的干扰项只显示中文意思；孩子从不在英文拼写之间做选择，也从不根据中文挑英文拼写。
- 阶段 1 从不截断放不下的文字（截断的单词就是拼写错误），而是拒绝这张卡；放不下的音标行会被隐藏。
- 阶段 2 只有在 `example_cloze` 恰好等于把条目文字替换为 `____` 后的例句时，才使用挖空例句正面。
- 阶段 3 从不把错误字母块写入空格，单词骨架的字符串在一张卡内也从不改变。
- `tests/test_vocab_sim.c` 在每个模拟步骤后检查每个视图模型，覆盖静音与非静音、所有阶段和所有结果，出现其他英文字符串即失败。

另外，填空校验器（主机测试）拒绝替换后会拼成词库单词、常用英文单词或屏蔽词的错误字母块（第 13.4 节），
因此阶段 3 中被否定的选项本身绝不是另一个单词的正确拼写。

| 音标 | 英式宽式音标，采用国内教材常用的 OALD 风格：不标“(r)”、不加音节点、保留长音符号、g 用 U+0261；单词音频保持美式英语 |
| 发布 | 包含 Windows 语音测试音频的固件保持私有，绝不发布 |
| 音频不进 Git | 由于该 fork 是公开的，音频及其清单在本地生成并被 Git 忽略；仓库和 CI 构建的固件没有单词音频，本地构建在存在本地音频包时将其嵌入 |

### 12.2 与原始设计文档的偏离

原始设计文档是一份 17 页的中文方案，涵盖学习科学依据、三阶段卡片流程、状态机、参考代码和预处理脚本。其参考代码仅作参考。

| 原始设计 | 单词伙伴 | 原因 |
| --- | --- | --- |
| 声明了错题解锁事件但从未使用；状态图中为 1.2 秒，正文中为 1.5 秒 | 明确的 1500 毫秒锁定，开始和结束时都清空队列，之后只有正确的键能继续 | 原设计从未真正强制停留 |
| 突击检查测的是下一个词；回滚只重置上一个词 | 检查自评过的某个词（不是最后一个）；失败则作废整轮自评 | 检查必须验证孩子做出的自评 |
| 进度数组只有一组的大小 | 整个词库按 uid 保存每词记录；带版本号、分块并有 CRC 的 NVS 格式 | 进度必须跨练习组和词库更新保留 |
| 卡背“忘了”直接把词送回阶段 1 | “等下考我”：两张卡之后的阶段 1 检查卡 | 与原设计自己的措辞一致；立即重复只考短时记忆 |
| 没有跨练习组的选词 | 先按逾期程度选到期复习，再选新词，再提前复习 | 间隔重复需要它 |
| 阶段 3 没有退回方案 | 没有填空数据的单词和短语使用阶段 2 | 并非每个条目都有安全的挖空 |
| 每个词固定一个 `lure_meaning` | 用注入的随机数按类别选干扰项 | 固定组合会变成位置线索 |
| 阶段 3 的晃动重试与通用停留没有统一 | 第一次答错 = 晃动并重试；最后一次答错 = 揭示加通用停留 | 统一的错误处理模型 |
| 每次开机直接进入五词挑战 | 开机显示主页；按一次 OK 开始 | 避免在书包或教室里突然出声；宠物才是吸引点（用户决策） |
| “太简单”的检查立即出现 | 检查卡在两张卡之后出现 | 完整拼写刚刚还在屏幕上 |
| 阶段 3 按 OK 播放分音素拼读（/b/ /ʌ/ /s/） | 重播整个单词 | 离线 TTS 无法可靠地生成单独音素；已延后 |
| 意思和徽标旁边用 emoji；卡背有图片和词性 | 没有 emoji 或图片；只用中文文字；状态图标用 LVGL 符号 | emoji 无法显示；图片已延后；每屏最多五行信息 |
| 长按 OK 是全局“返回” | 长按 OK 打开暂停卡（继续或回主页） | 按 OK 稍久不应丢掉一整组练习 |
| 单词读音用云端 `edge_tts` 神经语音 | 离线 Windows System.Speech 语音；音频仅供测试且保密 | 离线要求；音频随 Windows 授权，只作测试（用户决策） |
| 跟读：离线按音量或 VAD 给星，在线用云端打分 | 取消云端打分；跟读延后 | 声音不离开设备（用户决策） |
| 30 秒无操作关闭背光 | 20 秒变暗，30 秒熄屏并保存，再过 120 秒深度睡眠 | 小电池穿戴设备的续航 |
| 阶段 2 正面任意键立即翻面 | 前 1000 毫秒忽略按键 | 迫使孩子先尝试回忆 |
| 用 `lv_font_conv` 生成中文子集；英文用 Montserrat 28 | 用 Pillow/FreeType 生成并逐像素校验；Noto Sans SC 与 Andika | `lv_font_conv` 在当前 Node.js 下位图损坏；Andika 的字形对孩子友好 |
| 单词超过 10 个字母就用小字号 | 用真实字体按像素宽度判断（196 px） | 字母宽度差别很大 |
| 音频包放在独立数据分区，用 `esp_partition_read` 读取 | 嵌入应用镜像、原地读取的自描述音频包：本地构建用本地测试音频包，其他情况用提交到仓库的空音频包 | 约 250 KB 放得下；默认分区表保持不变；私有音频不进入 Git；流水线可以重新评估 |
| 每五个词写一次进度 | 在保存点（小结、熄屏、暂停后回主页、深度睡眠、低电量）且音频空闲时写入 | 减少断电损失，并让 Flash 写入避开播放 |
| 每次状态变化都 `xQueueReset` | 清空队列但保留 PRESS/RELEASE 记录 | 丢失的 RELEASE 会被当成按住的键，从而阻塞输入 |
| 250 毫秒冷却从卡片渲染开始计 | 从按下时刻开始计 | 单击在松开后约 180 毫秒才到达，否则条件反射式的按键会漏过 |
| 32 位 `global_session_id` | 16 位 tick，在 65535 处饱和 | 足够用几十年；记录更小 |
| 32 x 32 或 64 x 64 像素画宠物 | 宠物由 80 x 80 方框内最多 18 个 LVGL 矩形绘制 | 不需要图片素材；便于按成长阶段换色 |
| 示例中有六个类别 | 测试词库有十个类别 | 每个词都需要来自许多其他类别的干扰项 |

### 12.3 工程决策

- `VOCAB_MIN_PRESS_MS` 为 30 而不是 50：对孩子来说，丢掉一次真实点击比偶尔出现幻影按键更糟；在 5 毫秒轮询和两次去抖下，
  ADC 扫过造成的幻影最多约 15 毫秒。
- `CONFIG_BT_ENABLED=n`，`main` 只依赖 `bsp`、`esp_hw_support`、`esp_timer` 和 `nvs_flash`；基线演示源码保留在磁盘上供上游主机测试使用，但不编译。
- LVGL 内存池为 48 KB（第 2.5 节）。
- 单独的音标字体角色让 a 与 ɑ 可以区分（第 10.4 节）。
- O11 还会恢复被作废自评的“曾经掌握”标志；单词在卡片开始时被标记为见过。
- 只有检查卡确实能插入并出题时才提供“太简单”。
- 音频任务的优先级高于应用任务和 LVGL 任务，被打断时淡出 4 毫秒，报告空闲前写 96 毫秒静音；提示音电平为 -6、-9、-12 dBFS；
  有六段音频用到了峰值限制器。
- 阶段 1 从不截断文字，并隐藏放不下的音标行；锁定只在截止时间到达后结束。
- 阶段 2 在正面截止时间到达时即使定时器事件尚未到达也接受翻面，并且只在第 11 节的完全匹配检查通过后才使用挖空例句正面。
- 阶段 3 在第二次作答期间保留重试提示，锁定期间停止闪烁。它的屏蔽词表以 ROT13 编码存储，儿童产品的源代码中不会直接拼出冒犯性词语。
- 不自动擦除 NVS（仓库规则）：存储问题导致进入易失模式。
- 音频包自带索引和校验和，因此固件中没有生成的 C 数据，缺失或来路不明的音频包退化为“没有音频”，本地构建和公开构建使用同一份代码（第 9.2 节）。
- 评审与 QA 修复轮次（不改变学习行为）：双击从第一次按压起作为一个手势判断（第 6 节）；在主页上，音量浮动提示暂时取代开始提示行；
  从小结回到主页时停止播放；插入卡片后 `n/N` 立即显示新的 N；阶段 3 中 WORD_PULSE 的下划线位于单词骨架文字下方 2 px 处，而不是空格框下方，
  因此不再压到提示语。

## 13. 延后流水线的词库数据契约

把用户提供的词表转换成固件数据的流水线已延后，其输入格式和工具都尚未确定。本节确定它必须产出的内容，
使新词库可以替换测试词库，除下列限制外不需要改代码。

### 13.1 产出

| 产出 | 格式 | 检查者 |
| --- | --- | --- |
| 词库表 | 按课程顺序排列的 `vocab_entry_t` 行的 C 源文件，形式同 `main/vocab_bank.c`，通过 `vocab_bank_builtin()` 提供 | `tests/test_vocab_bank.c`、`tests/test_vocab_lure.c`、`tests/test_vocab_cloze.c` |
| 单词音频 | 第 9.2 节所述的自描述音频包和清单；在语音允许再分发之前不进入 Git | `build_clips.py --check`、`tests/test_vocab_adpcm.c`、`tests/test_vocab_clips.py` |
| 字体子集 | 重新生成、覆盖所有新字符的 `vocab_font_*.c` 与字符清单 | `vocab_fonts.py --check` |

### 13.2 条目字段

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `uid` | uint16 | 非零、唯一且永久不变；绝不复用或重新编号。进度和音频都以它为键。测试词库按类别编号（101-1003） |
| `text` | ASCII 字符串 | 可打印字符，1-20 个（`VOCAB_TEXT_MAX_CHARS`），首尾无空格；含空格即为短语（PHRASE） |
| `ipa` | UTF-8 或 NULL | 两端带斜杠的英式宽式音标（第 13.5 节）；句子式短语为 NULL |
| `zh` | UTF-8 | 只含汉字，1-6 个码位（`VOCAB_ZH_MAX_CHARS`） |
| `category` | uint8 | 从 1 开始；测试校验范围为 1-10（`VOCAB_CATEGORY_MAX`） |
| `cloze_pos`、`cloze_right`、`cloze_wrong` | uint8、两个字符串 | 全有或全无；见第 13.4 节 |
| `example` | ASCII 字符串 | 最多 30 个字符（`VOCAB_EXAMPLE_MAX_CHARS`），恰好包含一次 `text` |
| `example_cloze` | ASCII 或 NULL | 恰好是把 `example` 中的 `text` 替换为 `____` 的句子，或为 NULL |
| `example_zh` | NULL | 保留字段；本期不显示 |

表中顺序就是课程顺序，决定新词出现的先后。运行时按线性查找条目，存储模块会自行按 uid 排序记录，因此 uid 不必升序；
但当前的词库测试要求 uid 升序，流水线要么保持升序（例如由年级、学期、单元和序号推导 uid），要么有意放宽这项测试。

### 13.3 类别与干扰项

阶段 1 要求每个条目都至少有一个类别不同、意思不同且意思互不包含的其他条目；否则这张卡会退回阶段 2。测试词库还保证
每个单词在至少 8 个其他类别中有同类干扰项、每个短语在至少 2 个其他类别中有，使干扰项在不同练习组之间有变化。

### 13.4 填空数据

- 字母块选择（由 `vocab_cloze_choose()` 实现）：按优先级取第一个通过校验的字母块：(1) 元音组合或 r 控元音
  （ee ea oo ou ai ay oa ow ue ui ar er ir or ur）；(2) 辅音二合字母（sh ch th ph ck wh）；(3) 单个元音或近音字母（a e i o u、y、s/z、c/k）；
  都不行则不设填空数据。人工整理的条目可以覆盖自动选择，但须记录理由（测试词库中有五个：bike、nose、yellow、water 和 Good morning，
  理由写在对应条目旁）。
- 形状：`cloze_right` 和 `cloze_wrong` 是等长、互不相同的 1-3 个小写字母；`text` 在字节 `cloze_pos` 处包含 `cloze_right`；短语中的空格保留。
- 允许的组合：a、e、i、o、u 中任意两个；i/y；s/z；c/k；c/s；ph/ff；ee/ea；oo/ou；oa/ow；ou/ow；ai/ay；ue/oo；ui/oo；
  ar、er、ir、or、ur 中任意两个；sh/ch。
- 用 `cloze_wrong` 替换后得到的词元不得是任何词库条目文字或例句中的词元，不得出现在常用词表中
  （`assets/wordlists/common-words-35.txt`，46,219 个词形，仅主机测试使用），也不得出现在内置屏蔽词表中。
- 必须拒绝的情况：bag a->i（big）、cat a->u（cut）、pear ea->ai（pair）、pear ea->ee（peer）、bread ea->ee（breed）、read ea->ai（raid）、
  blue ue->ew（blew）。

### 13.5 音标

OALD 风格的英式宽式音标，两端带斜杠，只用可打印 ASCII 加 16 个符号：ˈ ˌ ː æ ə ɑ ɒ ɔ ʊ ʌ ɪ ŋ θ ʃ ʒ ɡ（g 用 U+0261）。
增加新符号时，必须同时扩充词库测试、字体工具的音标集合和 F_IPA 子集。

### 13.6 布局

每条文字都必须满足字号规则（36 px 或 28 px 下一行不超过 196 px，或 22 px 下最多两行、每行不超过 200 px）。用当前字体，最宽的测试条目也都放得下：
每个例句在 18 px 下一行放得下（最宽 199 px），最宽的中文意思在 22 px 下为 132 px。生成器应该用真实字体预先测量，
放不下的条目直接拒绝，而不是依赖设备。

### 13.7 音频

每个 uid 一段音频，采用第 9.2 节的音频包格式：单词最长 1.6 秒、短语最长 2.5 秒，语音 RMS 为 -18 +/- 1 dBFS，峰值不高于 -1 dBFS，
开头静音不超过 40 毫秒、结尾静音不超过 80 毫秒，并附带记录来源和哈希的清单。可以提交或发布的音频包需要许可允许再分发的语音；
在此之前音频包只保留在本地。嵌入式音频包上限为 600 KB 和 256 段，按目前的平均大小（约 5.4 KB）约可容纳 110 段，
因此完整词库需要另外的存储方案：数据分区或更低码率的编码。

### 13.8 字体

用新词库重新生成字体子集；字符清单会自动收集每个 `zh`、`ipa` 和英文字段。原始设计估计完整的小学词库约有 300-500 个不同汉字；
所有生成字体应控制在 220 KB 以内。

### 13.9 进度兼容

进度以 uid 为键。更换词库会改变词库指纹，下次保存时触发全部重写：仍在词库中的 uid 保留进度，被移除的 uid 失去进度，新 uid 从头开始。
因此给某个词重新编号就会重置这个词的进度。

### 13.10 容量限制

| 限制 | 当前值 | 位置 | 扩容方式 |
| --- | --- | --- | --- |
| 可跟踪的词库条目 | 256 | `VOCAB_RECORDS_MAX` | 提高该值（每个词 8 字节内存，外加存储模块的逐条数组） |
| 启动时读取的进度块键 | 32（2,048 个词） | `VOCAB_STORE_PROBE_CHUNKS` | 随词库提高 |
| NVS | 24 KB，约 1200 个词 | `partitions.csv` | 48 KB 或更大；会重置进度（第 8.5 节） |
| 嵌入式音频包 | 600 KB 和 256 段 | `VOCAB_CLIP_BLOB_MAX_BYTES`、`VOCAB_CLIPS_MAX` | 数据分区或其他编码 |
| 字体 | 合计 220 KB | 非功能性要求 | 减少字号或字符 |
| 文字长度 | 20 / 6 / 30 个字符 | `VOCAB_TEXT_MAX_CHARS`、`VOCAB_ZH_MAX_CHARS`、`VOCAB_EXAMPLE_MAX_CHARS` | 先评审布局 |
